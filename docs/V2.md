# Pozzy v2 backlog

Everything deliberately left out of v1 (plan section 11) plus what the four streams punted. Nothing here blocks daily use of v1.

## From plan section 11 (out of v1 by decision)

- Sending or replying to email.
- Gmail API and labels (v1 is IMAP read-only; labels only via `X-GM-LABELS` where Gmail exposes them).
- Telegram bot for input and notifications. `POST /api/captures` is the endpoint it will hit.
- Shared use or multi-user (Supabase user id is not stored on rows yet; RLS not enabled).
- Trading 212 or finance widgets.
- Native iOS app (v1 is a PWA).
- Offline-first PWA sync (v1 service worker: network-first `/api`, cache-first assets, app shell precached).
- Recurring tasks (use trackers for habits).

## Punted by stream A (local modules)

- Server-side hours timer. v1 keeps the running timer in browser localStorage; a Telegram "start/stop" needs it in the API.
- Claude parsing from the Tasks quick-add bar. v1 routes natural language through the Capture bar instead.
- Areas are read-only (seeded four). No edit UI.

## Punted by stream B (calendar)

- Editing single occurrences of recurring iCloud events (v1 returns 409 `recurring_not_editable`); writing overrides into the master VEVENT.
- Manual `POST /api/calendar/sync` runs synchronously and writes no `job_runs` row; only the scheduled job logs.
- Events created from the Agenda have `etag` null until the next sync fills it (harmless, one extra update).
- Calendar selection defaults to every calendar incl. Reminders and Holidays until unticked in Settings.

## Punted by stream C (mail)

- Sync throughput is about 1 message per second on Gmail; a busy inbox backfills over several 15 minute cycles (500 per run cap).
- Gmail exposes labels only for messages that carry one beyond INBOX.
- No thread grouping (`thread_hint` stored, unused in the UI).
- "Handled" is local only; no IMAP flag changes by design.

## Punted by stream D (AI)

- Haiku prompt caching only engages above a 4096 token prefix; the classification system prompt is smaller, so `cache_read_input_tokens` stays 0 until the prompt grows.
- `PRICES` in `claude_client.py` is a hardcoded September 2026 table; update when Anthropic changes prices or when `.env` moves to `claude-sonnet-5`.
- `_call` commits the SQLAlchemy session when it logs an `ai_calls` row; callers must not hold uncommitted work they want rolled back.
- Weekly review: reflection quality depends on a full week of data; the first review after release will be thin.

## Found during integration (stream E)

- Slot suggestions use a deterministic pre-shortlist of 12 candidates before Claude ranks; a smarter shortlist (respecting energy or area per day) is possible.
- The three-do suggestion and briefing run once per day; there is no "regenerate with edits" loop beyond the widget button.
- Gunicorn must stay at `--workers 1` because APScheduler runs in-process. Moving the scheduler to a separate Railway service unlocks more workers.
- Push notifications (PWA) for briefing and deadline alerts.
- E2E browser tests. v1 was clicked through manually against a local API with a minted HS256 session; no Playwright suite exists.

## Punted by the design pass (2026-09-15)

- Replace the eight `window.prompt` and `window.confirm` call sites (tasks complete with minutes, tracker numeric entry, deletes in tasks, notes, trackers, courses, applications, review finalize) with inline confirms and an inline number field. Control flow changes, so it was out of scope for the presentation-only pass.
- Seeded Work area colour (#dc2626) sits next to the brand red; consider a different hue when the areas get an edit UI.
- `Branding/pozzy-svg.svg` is exported green; confirm or re-export, then the login and top bar can use the vector wordmark instead of pozzy.png.
- Mail detail on the phone shows both the sheet close button and the detail's own Close link.
- Skeleton loading states exist for lists; the agenda grid and widgets still render nothing until data arrives (by the widget contract).
